# How this course works

## Understand, then operate

This course is built around a simple loop. First understand what a step is supposed to do. Predict the result, run the step, inspect the evidence, and explain any difference between your prediction and what happened. That loop builds transferable judgment instead of button memory.

## Make the result test you

Before running a command or changing a FEAT setting, state what you expect. A prediction makes the output diagnostic. If the output differs, the gap may reveal a path error, a misunderstood parameter, or a scientific assumption that needs revision.

## Use two working spaces

Keep the explanation beside the working environment. Read one step, make a prediction, and then perform it yourself. Use a notes file to record commands, observations, and unresolved questions. The notes become part of your reproducible reasoning.

## Expected output is a check

An example is not an answer key to copy. Look at it after you have made a prediction and run the step. Then compare structure, not every character, because file paths and exact values may legitimately differ across environments and datasets.

## Practice the reasoning loop

Use each lesson as a cycle of understanding, prediction, action, inspection, and explanation. That habit is more valuable than memorizing a menu or command sequence, because it continues to work when the interface or dataset changes.
